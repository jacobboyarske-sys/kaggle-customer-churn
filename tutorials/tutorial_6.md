## Шаг 1. Тюнинг гиперпараметров CatBoost

В туториале 5 использовались параметры "на глаз" (`depth=6`, `learning_rate=0.05`).
CatBoost умеет искать их сам через `randomized_search`, используя ту же схему
кросс-валидации, что и раньше:

```python
from catboost import CatBoostClassifier
from sklearn.model_selection import StratifiedKFold

skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

model = CatBoostClassifier(
    iterations=300, eval_metric="AUC", random_seed=42, verbose=False,
    cat_features=cat_features,
)
param_distributions = {
    "depth": [4, 6, 8],
    "learning_rate": [0.05, 0.1],
    "l2_leaf_reg": [3, 5, 10],
}
search_results = model.randomized_search(
    param_distributions,
    X=X_raw, y=y,
    cv=3,
    n_iter=6,
    partition_random_seed=42,
    verbose=False,
)
print(search_results["params"])
```

**Ограничьте бюджет поиска.** Первая версия этого шага (`iterations=1000`,
сетка 4×3×4=48 комбинаций, `cv=skf` на 5 фолдах, `n_iter=15`) реально считалась
дольше 30 минут на обычном ноутбуке и была прервана — CatBoost перестраивает
внутренний `Pool` на каждой комбинации параметров, и это недёшево с
категориальными признаками. `cv=3` (простое число фолдов, не сам объект
`StratifiedKFold`) и `iterations=300` для *поиска* параметров — практичный
компромисс: сначала дёшево нашли примерный диапазон, затем в шаге 1
(`run_cv`) с найденными параметрами оцениваем уже честно на тех же 5 фолдах,
что и остальные модели туториала.

`l2_leaf_reg` — L2-регуляризация на весах листьев дерева (аналог `alpha` в
`Ridge`-регрессии): больше значение — модель "осторожнее", меньше риск
переобучиться на шуме, но и меньше гибкости. `n_iter=15` — сколько случайных
комбинаций параметров попробовать (полный перебор по сетке 4×3×4=48 комбинаций
на 5 фолдах занял бы значительно дольше).

**Грабли по дороге**: `cat_features` здесь передан в **конструктор**
`CatBoostClassifier`, а не в сам вызов `randomized_search` — если его туда не
передать, `randomized_search` попробует превратить `Geography` в число и упадёт
с `CatBoostError: Bad value for num_feature... Cannot convert 'France' to float`.
В обычном `model.fit(...)` (туториал 5) `cat_features` можно передавать прямо в
`fit`, но `randomized_search`/`grid_search` ожидают его уже в конструкторе модели.

Обучите модель с найденными параметрами через тот же цикл `run_cv` из туториала 5
и сравните OOF ROC AUC с 0.9289.

## Шаг 2. Второй бустинг — LightGBM

Для блендинга полезны модели, которые **ошибаются по-разному**. CatBoost и
LightGBM строят деревья по-разному (CatBoost — симметричные деревья и особый
механизм борьбы с переобучением на категориях, LightGBM — leaf-wise рост дерева),
поэтому их ошибки обычно не полностью совпадают.

Категории в LightGBM задаются через тип данных `category`, а не отдельным
параметром со списком колонок:

```python
import lightgbm as lgb

X_lgb = X_raw.copy()
for col in cat_features:
    X_lgb[col] = X_lgb[col].astype("category")
```

Дальше — тот же цикл по 5 фолдам, что и для CatBoost в туториале 5, но с
`lgb.LGBMClassifier`:

```python
model = lgb.LGBMClassifier(
    n_estimators=1000, learning_rate=0.05, random_state=42,
)
model.fit(
    X_tr, y_tr,
    eval_set=[(X_val, y_val)],
    eval_metric="auc",
    callbacks=[lgb.early_stopping(50, verbose=False)],
)
```

Сохраните OOF-предсказания LightGBM (`oof_lgb`) отдельно от CatBoost (`oof_catboost`)
— оба понадобятся в шаге 4.

## Шаг 3. Пересчитать OOF логрегрессии на тех же фолдах

В туториале 4 логрегрессия оценивалась на одном `train_test_split`, а не на
5 фолдах — эти предсказания нельзя напрямую смешивать с OOF из шагов 1-2, потому
что они считались на разных подвыборках. Прогоните тот же `Pipeline` из туториала
4 (с лучшим набором признаков: клип `EstimatedSalary`, `NumOfProducts` как
категория, `AgeGroup`) через цикл по **тем же** `StratifiedKFold(random_state=42)`,
что и бустинги, и получите `oof_logreg`.

Это не лишняя работа ради дотошности: блендинг двух моделей, оценённых на разных
подвыборках, даёт invalid/оптимистичную оценку итогового ROC AUC — типичная
ошибка при первом знакомстве с ансамблями.

## Шаг 4. Блендинг — подбор веса смеси

Простейший вид ансамбля — взвешенное среднее вероятностей:

```python
import numpy as np
from sklearn.metrics import roc_auc_score

best_alpha, best_auc = 0, 0
for alpha in np.arange(0, 1.01, 0.05):
    blend = alpha * oof_catboost + (1 - alpha) * oof_lgb
    auc = roc_auc_score(y, blend)
    if auc > best_auc:
        best_alpha, best_auc = alpha, auc

print(f"best alpha={best_alpha:.2f}, blended OOF ROC AUC={best_auc:.4f}")
```

`alpha` — вес CatBoost в смеси (0 = чистый LightGBM, 1 = чистый CatBoost).
Переберите так же трёхкомпонентную смесь (CatBoost + LightGBM + логрегрессия) —
удобно через вложенный перебор весов с шагом 0.1, суммирующихся в 1. Если лучший
`alpha` для двух моделей окажется близко к 0 или 1 — это сигнал, что вторая модель
не добавляет разнообразия (её вклад в смесь минимален), а не что метод не работает.

## Как использовать Claude Code на этом этапе

- Если `randomized_search` работает подозрительно долго — обсудите, стоит ли
  уменьшить `n_iter` или сетку параметров, прежде чем просто ждать.
- Спросите "почему": *"Почему для блендинга используем OOF-предсказания, а не
  просто score каждой модели на Kaggle?"* (ответ завязан на то, зачем вообще
  нужна кросс-валидация, а не один сабмит для сравнения моделей).
- Не просите "сделай тюнинг и ансамбль" одним запросом — это тот случай, когда
  разбор `randomized_search` по шагам и ручной подбор `alpha` дают понимание,
  которое не получить, просто увидев готовый результат.

## Шаг 1. Feature importance из CatBoost

```python
importances = final_catboost.get_feature_importance(prettified=True)
importances
```

`prettified=True` возвращает отсортированную таблицу "признак → вклад в %"
(по умолчанию метод `PredictionValuesChange`: насколько в среднем меняется
предсказание, если исключить признак). Это самый быстрый способ понять, на что
опирается модель, но у него есть ограничение: он не показывает *направление*
влияния (растёт ли риск оттока с ростом признака или падает) и не объясняет
отдельные предсказания — для этого нужен SHAP.

## Шаг 2. SHAP — глобальная картина

```python
import shap

explainer = shap.TreeExplainer(final_catboost)
shap_values = explainer.shap_values(X_raw)

shap.summary_plot(shap_values, X_raw)
```

`TreeExplainer` — вариант SHAP, оптимизированный для деревьев (быстрый и точный,
в отличие от универсального `KernelExplainer`). `summary_plot` показывает для
каждого признака: разброс его влияния на предсказание по всем клиентам
(по оси X — вклад в лог-odds, по цвету точки — было ли значение признака низким
или высоким). Это отвечает сразу на два вопроса: какие признаки важны **и** в
какую сторону они толкают предсказание.

## Шаг 3. SHAP — разбор одного клиента

```python
client_idx = 0  # любой конкретный клиент из train

shap.waterfall_plot(
    shap.Explanation(
        values=shap_values[client_idx],
        base_values=explainer.expected_value,
        data=X_raw.iloc[client_idx],
        feature_names=X_raw.columns.tolist(),
    )
)
```

`waterfall_plot` показывает путь от "среднего предсказания по всем клиентам"
(`base_values`) до конкретного предсказания для этого клиента — какие признаки и
на сколько сдвинули вероятность вверх или вниз. Найдите клиента с высокой
предсказанной вероятностью оттока (`final_catboost.predict_proba(X_raw)[:, 1]`,
отсортировать по убыванию) и разберите, что именно модель посчитала тревожными
сигналами именно для него.

Главные уроки пути:
- **Самый большой отдельный скачок** — не тюнинг и не ансамбли, а понимание
  одного признака (`NumOfProducts`) через EDA и либо его правильное кодирование
  (туториал 4), либо смена модели на ту, что находит нелинейности сама
  (туториал 5).
- **Смена модели (логрегрессия → бустинг) дала больше**, чем весь ручной feature
  engineering вместе взятый — деревья сами нашли то, что в туториале 4 искали
  руками.
- **Тюнинг и блендинг дали скромный, но положительный эффект** в самом конце —
  типичная картина, когда основная часть пути уже пройдена: дожимать последние
  проценты сложнее, чем найти первые большие улучшения.

## Как использовать Claude Code на этом этапе

- Если результат SHAP расходится с ожиданиями из EDA — сначала попробуйте
  объяснить расхождение сами (мультиколлинеарность? взаимодействие признаков?),
  потом сверяйтесь с Claude Code.
- Спросите "почему": *"Почему TreeExplainer, а не KernelExplainer?"* — хороший
  повод разобраться, почему для деревьев есть специализированный, точный и
  быстрый метод, а не только универсальный приближённый.

# Kaggle: Predicting Customer Churn

Учебный pet-проект: решение соревнования Kaggle
["Predicting Customer Churn: Binary Classification"](https://www.kaggle.com/competitions/predicting-customer-churn-a-real-world-binary-classification-challeng) —
бинарная классификация оттока клиентов банка, метрика ROC AUC. Подробный пошаговый
план — в [tutorials/README.md](tutorials/README.md); каждый этап оформлен отдельным
нумерованным файлом `tutorials/tutorial_N.md`.

## Главное правило работы над этим проектом

Это учебный проект: **код пишет пользователь, а не Claude Code за неё**. Цель —
вспомнить, как устроен ML-пайплайн от сырых данных до сабмита на Kaggle, а не
получить максимальный score как можно быстрее. Из этого следует:

- Не пиши сразу целые ноутбуки/модули за один запрос без обсуждения — предлагай
  план, дай пользователю написать код самостоятельно, помогай точечно (объяснение,
  ревью, подсказка по конкретной функции/ячейке).
- Для новых крупных шагов (новый этап туториала, новая модель, новая стратегия
  валидации) сначала предложи план и обсуди его, прежде чем писать код.
- Если пользователь просит написать код целиком — это нормально, но по умолчанию
  предпочитай режим "подсказчика и ревьюера", а не "автора".
- Объясняй *почему*, а не только *что* — особенно для ML-решений: почему эта модель,
  эта метрика валидации, этот способ кодирования категорий, а не другой.

## Соревнование

- Комьюнити-соревнование (без призов, чисто учебное), проходило 5 фев – 22 мар 2026,
  сейчас в режиме Late Submission — сабмиты и score всё ещё считаются, просто без
  влияния на официальный (уже зафиксированный) рейтинг.
- Данные — синтетика по мотивам классического датасета Bank Customer Churn:
  `CreditScore`, `Geography`, `Gender`, `Age`, `Tenure`, `Balance`, `NumOfProducts`,
  `HasCrCard`, `IsActiveMember`, `EstimatedSalary` → таргет `Exited` (0/1).
- Файлы: `train.csv`, `test.csv`, `sample_submission.csv`.
- Метрика: **ROC AUC**.
- Формат сабмита: CSV `id,Exited`, где `Exited` — вероятность (не класс 0/1).
- **Цель проекта**: попасть в топ-10 финального лидерборда, это соответствует
  ROC AUC ≈ 0.933+ (10-е место — 0.93344; места 1-12 идут плотной группой
  0.928–0.938, дальше резкий обрыв до 0.85 и ниже у тех, кто переобучился или
  ошибся в валидации).

## Соглашения

- Код и идентификаторы — на английском, комментарии/докстринги — по ситуации, но
  общение с пользователем в чате — на русском.
- Маленькие, атомарные изменения; коммит после каждого законченного шага/этапа.
- Перед коммитом — пользователь сам просматривает diff.
- Сырые данные (`data/raw/`) и сгенерированные сабмиты (`submissions/`) в git не
  попадают — скачиваются заново через Kaggle CLI / перегенерируются кодом.
- Локальный CV score каждой существенной попытки фиксируется (в ноутбуке или
  отдельном логе экспериментов), чтобы видеть прогресс и не терять историю.
